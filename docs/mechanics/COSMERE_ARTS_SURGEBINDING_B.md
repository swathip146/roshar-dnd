# Surgebinding Invested Arts — Catalogue B (Lightweaver, Elsecaller, Willshaper, Stoneward, Bondsmith)

Source: `parsed_data/cosmere-5e-the-invested-arts-of-the-cosmere-v2-0/docling.md`, Chapter 1 "Surgebinding Invested Arts" (lines 123-8859). Index lists: lines 123-319. Art descriptions: lines 320-8858 (alphabetical after the 10 Basic Surge cantrips).

Scope: every art whose byline names Lightweaver, Elsecaller, Willshaper, Stoneward, or Bondsmith, cantrips through 9th level. Arts shared with Windrunner/Skybreaker/Dustbringer/Edgedancer/Truthwatcher are included here in full (a companion catalogue, "Catalogue A," covers those five orders and will re-list the same shared rows from its own side — this is intentional, per the task's overlap note).

**Read this first — the Bondsmith answer:** Bondsmith does **not** appear anywhere in this book. A file-wide `grep -n "Bondsmith"` over the full 19,794-line `docling.md` returns **zero matches** — not just in Chapter 1, but in the entire document (Allomancy chapter included). This book does not fill the gap that `COSMERE_MECHANICS.md` recorded (Bondsmith deferred to "Hoid's Guide to the Cosmere"). The project's 9-of-10-orders gap for Bondsmith remains unresolved after this extraction. Its two named surges, Tension and Adhesion, both appear in this book, but only as *other orders'* cantrips: Tension is a Stoneward cantrip (line 556) and Adhesion is a Windrunner cantrip (line 321) — neither is attributed to Bondsmith anywhere, and no Bondsmith-specific art, class feature, or index list exists.

**A second, unexpected finding — Willshaper's leveled arts are not indexed, but do exist in the body.** The chapter's own index (lines 123-319) lists leveled arts for every order except Willshaper and Stoneward, which are shown with cantrips only (Willshaper: Cohesion, Transportation; Stoneward: Cohesion, Tension — lines 303-311). This is a genuine gap in the source's index section (flagged below). However, a full-text scan of every art byline in the body turns up exactly **three** Willshaper leveled arts, tagged with an order-specific surge label "Willshaper Cognitive Power" (apparently Willshaper's flavor name for its Transportation-based surge, analogous to "Elsecaller Inksurge"): *Detect Investiture* (1st, line 2676), *Locate Object* (2nd, line 5372), *Realmatic Door* (4th, line 6600). No comparable hidden tag exists for Stoneward anywhere in the chapter — Stoneward truly has cantrips only in this book (Cohesion, Tension; 0 leveled arts).

## Effect types an engine must support

Distinct mechanical shapes observed across the ~187 catalogued arts (Lightweaver/Elsecaller/Willshaper/Stoneward slice; Bondsmith contributes none). Mapped against the project's existing `maneuver_executor.py` node vocabulary (target/save/damage/attack/roll/ieffect2) per the task brief:

1. **Attack roll (ranged or melee) → on-hit damage.** e.g. *Ice Shard*, *Fire Bolt*, *Storm's Leash*, *Ash's Hand* (Clenched Fist). Maps to existing `attack` + `damage` nodes.
2. **Save-or-suffer full effect (no half on success).** e.g. *Cognitive Prison* (fail = full effect, success = partial-damage-then-end), *Torment* (binary threshold gate on HP, then ongoing debuff), *Charm Person/Creature*, *Sleep*. Maps to `save` node, but many of these are not simple pass/fail — they gate a *multi-turn state machine* (see item 8).
3. **Save-for-half (classic AoE damage).** e.g. *Fireball*, *Cone of Cold*, *Circle of Death*, *Meteor Swarm*, *Chain Lightning*. Maps cleanly to existing `save` + `damage` nodes if the interpreter supports an area/AoE target node — need to confirm `target` node supports "each creature in an X-ft sphere/cone/line/cube."
4. **Healing (single-target and AoE).** e.g. *Regrowth*, *Dispersed Regrowth*, *Immense Regrowth*, *Heal*, *Mass Regrowth* (though most of these top healing arts are Edgedancer/Truthwatcher, Lightweaver/Elsecaller get them via shared Progression tags in a few cases like *Decay to Healing*, *Sacrificial Regrowth*-adjacent). Needs a `heal` node — **not in the existing five node types.** `ieffect2` might currently absorb this generically, but a dedicated heal-amount-and-target node would avoid overloading `ieffect2`.
5. **Condition application (charm, frighten, paralyze, stun, blind, deafen, poison, restrain, prone, incapacitate, petrify).** e.g. *Hold Person*, *Charm Person*, *Cremflesh* (petrify via 3-strikes-you're-out save accumulation), *Confusion* (randomized per-turn behavior table). The "3 successes/3 fails" accumulator pattern (Cremflesh, Contagion) and the "roll d10/d6 for random behavior each turn" pattern (Confusion, Mindcast) are **not simple condition-apply-for-duration** — they need a stateful per-turn re-roll/counter mechanism. This is the single biggest gap: the existing node set (as named) has no obvious "recurring save with counter" or "random behavior table" node.
6. **Movement / forced movement / teleportation.** e.g. *Realmatic Door*, *Stormstep*, *Fissure of Displacement* (push/pull), *Disrupture* (push-or-pull choice), *Gravitation* cantrip (Lash a creature in a chosen direction). Needs a `move`/`teleport` node — not in the listed five.
7. **Terrain / object / structure creation (walls, spheres, zones, difficult terrain).** e.g. *Wall of Fire/Ice/Stone/Water*, *Sleet Storm*, *Entangle*-family, *Thorn Growth*. These have HP/AC as objects (Wall of Ice: AC 12, 30 HP/section) and can be independently damaged/destroyed. Needs a `create_object`/`create_zone` node with its own HP/AC sub-schema — not in the listed five.
8. **Summoning (controlled creatures).** *Conjure Castweaving* — summons CR-budgeted creatures with a modified stat block (no mental-stat checks, uses caster's save proficiency, shared group initiative, 300-ft leash-to-zero-HP). This is the most structurally demanding single art in the catalogue and needs a `summon` node plus stat-block-override logic; nothing in the current five node types covers this.
9. **Buff / debuff (temporary stat/AC/resistance/advantage changes without a discrete "condition" name).** e.g. *Tough Skin* (+2 AC), *Haste* (double speed, +2 AC, extra limited action), *Slow* (halved speed, −2 AC/DEX, single-attack cap), *Quartzskin* (damage-type resistance). Could be modeled as `ieffect2` generically, but the sheer diversity of stacking/interaction rules (Haste's post-effect lethargy; Slow's 1-action-art delay-roll) suggests `ieffect2` needs to support a fairly rich effect-description schema, not just flat modifiers.
10. **Resistance / immunity grants (including "upgrade resistance to immunity on reaction," as in Essence Armor).** Sub-case of buff/debuff above but worth calling out because *Essence Armor*'s reaction-triggered resistance→immunity swap is a conditional state transition mid-effect, not a static buff.
11. **Illusion / sensory deception with an active disbelieve mechanic.** e.g. *Silent Lightweaving*, *Complex Lightweaving*, *Programmed/Recorded Lightweaving*, *Project Image*, *Mists* (redirect-attack ward). These need an "Investigation check vs caster's save DC to disbelieve" sub-node, plus, for *Lightwoven Terror* and similar, a "deals real damage only if the target still believes it" branch. Not covered by any of the five listed node types as named.
12. **Utility / divination / detection.** e.g. *Detect Investiture*, *Identify*, *Locate Object/Creature*, *Scrying*, *Espy*. Largely non-combat, low mechanical complexity, but *Scrying*'s variable-DC-by-familiarity (+5 heard-of / +0 met / −5 familiar / −4 extra if holding a personal item) is a small piece of conditional-DC logic worth flagging for a `roll`/`save` node's DC calculation.
13. **Reaction-triggered effects (interrupt/counter/defensive).** e.g. *Shield* (+5 AC on being hit), *Counter-Invest* (interrupt a spell being cast, level-gated success), *Fiery Rebuke*, *Astral Barbs* (force a reroll of another creature's success). These need the executor to support reactions keyed off *other creatures'* rolls (not just the caster's own trigger conditions), which is more than a simple `roll` node — it requires hooking into another actor's attack/save resolution mid-resolution.
14. **Crafting/transmutation, non-combat, DC-by-table.** *Soulcast* (Ten Essences ladder, DC = 15 + steps-apart, material consumed on any Investiture-check attempt, extra failure states at ≥5-over and natural-1). This is a unique, self-contained rules module; likely easiest to implement as a bespoke one-off resolver rather than force it through general node types.

**Summary of node types the task asked about, applied to this slice:**
- `target`, `save`, `damage`, `attack`, `roll` — sufickient for effect types 1-3 and simple parts of 12-13, **provided `target` already supports AoE shapes (sphere/cone/line/cube) and multi-target selection with an HP-ordered "fill until pool exhausted" mode** (needed for *Sleep* and *Prismatic Weaving*'s d-pool mechanic — verify this exists before assuming coverage).
- `ieffect2` — probably the current catch-all for buffs/debuffs/conditions, but the accumulator-save pattern (Cremflesh, Contagion) and randomized-behavior-table pattern (Confusion, Mindcast) push past what a flat "apply this named condition for N rounds" schema can express without added state.
- **Missing node types, by my read of what's needed:** `heal` (single/multi-target, no-effect-on-splinters flag is common enough to warrant a first-class field), `move`/`forced_move`/`teleport` (with push/pull/direction/distance parameters), `create_object`/`create_zone` (with independent HP/AC and duration-until-destroyed semantics), `summon` (CR-budget, stat-block override rules, leash distance), `illusion` (disbelieve-check sub-resolution, "real damage only if still fooled" branch), and a generalized **stateful-recurring-save** wrapper (so Cremflesh/Contagion/Confusion/Slow don't each need bespoke code).
