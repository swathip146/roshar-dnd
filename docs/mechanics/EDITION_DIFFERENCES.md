# D&D 5e Edition Differences: 2014 Basic Rules vs. 2024 SRD 5.2.1

**Purpose**: This project's vendored data (`data/rules/srd/monsters.json`) and
encounter-difficulty code are 2014-era, while a separate audit is cataloguing
the 2024 SRD as if it might replace or extend that data. This document
identifies every place the two rule sets disagree, and separately flags any
2014 mechanic with no 2024 SRD equivalent, so nothing is silently dropped
during that catalog work. It closes with a per-mechanic recommendation for
which edition this codebase should implement.

**Sources** (read directly, in full, for every claim below):
- 2014 — `parsed_data/dnd_basicrules_2018/docling.md` (13,162 lines, "D&D
  Basic Rules" — a free-to-download subset of the 2014 PHB/DMG/MM, not the
  full rulebooks; some tables that live only in the full PHB, e.g. the full
  Multiclassing Prerequisites table, are absent from this source and flagged
  below as "not in Basic Rules" rather than assumed absent from 2014 as a
  whole)
- 2024 — `parsed_data/srd_cc_v5.2.1/docling.md` (24,275 lines, the 2024 SRD
  under the Creative Commons license — also a subset of the full 2024
  PHB/DMG/MM)

**OCR/parsing caveats observed** (flagged, not guessed around):
- Many monster stat-block tables in both files are duplicated 6-10x
  horizontally by docling's table parser (e.g. 2014 lines 7772, 8648, 8704,
  8854, 8872; 2024 lines 17132-17139 for Air Elemental). This is a rendering
  artifact of the source PDF's multi-column stat-block layout, not a content
  difference — the underlying text is a single stat block repeated by the
  parser, not six different creatures.
- The 2014 file's table of contents (e.g. line 83) sometimes interleaves
  unrelated ToC entries into one garbled row; this is cosmetic and doesn't
  affect the rules text itself, which was read directly at cited line numbers.
- Where a rule's full text exists only in the full Player's Handbook/Dungeon
  Master's Guide and not in either "Basic Rules"/"SRD" excerpt (e.g. the 2014
  Multiclassing Prerequisites ability-score table), this is called out
  explicitly rather than treated as a real absence.

## 1. Rules that CHANGED between editions

| Mechanic | 2014 rule (line) | 2024 rule (line) | Impact on an implementation |
|---|---|---|---|
| **Exhaustion** | Six discrete levels, each with a distinct effect (1: disadvantage on ability checks; 2: speed halved; 3: disadvantage on attacks/saves; 4: HP max halved; 5: speed 0; 6: death). Table at `dnd_basicrules_2018/docling.md:12822-12829`. Removed 1 level per Long Rest (12837). | Single cumulative "reduce d20 rolls by 2 × level, reduce Speed by 5ft × level" penalty, no per-level effect table. Death still occurs at level 6. `srd_cc_v5.2.1/docling.md:12293-12299`. Removed 1 level per Long Rest (12299, 12525). | Complete mechanical rewrite, not a numeric tweak — a level-3 character in 2014 has disadvantage on attacks/saves but no numeric roll penalty; in 2024 the same level gives a flat -6 to every d20 roll and -15ft speed. Any exhaustion-tracking code keyed to the 2014 effect table (e.g., "if level>=3: disadvantage_on_attacks") is incompatible with a 2024 implementation and vice versa. Cannot be "patched" — needs a distinct code path per edition. |
| **Encounter building / difficulty** | 4 tiers (Easy/Medium/Hard/Deadly), per-character XP thresholds by level (`dnd_basicrules_2018/docling.md:12323-12347`), monster XP total is then scaled by a **group-size multiplier** (×1 for 1 monster up to ×4 for 15+, table at 12375-12381, adjusted further for party size <3 or ≥6 at 12387-12393). Also defines "Adventuring Day XP" per character (12417-12430) for daily budgeting. | 3 tiers (Low/Moderate/High), **XP Budget per Character** table (`srd_cc_v5.2.1/docling.md:13525-13549`) is multiplied by party size to get a flat XP budget; monsters' XP values are subtracted directly from that budget with **no group-size multiplier at all** (13551-13565). No "Adventuring Day" XP table appears in the 2024 SRD text read. | This is the single highest-risk divergence for the codebase, since CLAUDE.md states the encounter-difficulty code implements "XP thresholds + group-size multipliers" (the 2014 system). A 2024-faithful implementation must delete the multiplier step entirely and rescale thresholds (values differ starting at 3rd level Deadly: 2014 discrete threshold jumps vs. 2024's smoother "High" scaling — compare row-by-row, e.g. 2014 3rd-level Deadly=400 vs 2024 3rd-level High=400 — coincidentally equal at level 3 but diverge elsewhere, e.g. level 6: 2014 Deadly=1,400 vs 2024 High=1,400 also equal, but level 9: 2014 Deadly=2,400 vs 2024 High=2,600 — **not identical**, verify per level before reusing 2014 numbers as 2024 numbers). CR→XP and CR→Proficiency-Bonus tables themselves are unchanged (see §1 "CR/XP tables" row below) — only the *aggregation formula* changed. |
| **CR→XP and CR→Proficiency Bonus tables** | `dnd_basicrules_2018/docling.md:7256-7274` (PB by CR) and `:7344-7360` (XP by CR). | `srd_cc_v5.2.1/docling.md:16970-16992` (XP by CR) and `:16997-17004` (PB by CR, same values grouped into ranges). | **No change** — every XP and Proficiency Bonus value is identical between editions (verified per row, e.g. CR 5 = 1,800 XP / +3 PB in both; CR 20 = 25,000 XP / +6 PB in both). Only the encounter-difficulty *aggregation* formula above changed, not the per-monster inputs. Safe to keep as shared data. |
| **Weapon proficiency vs. Weapon Mastery / Armor Training** | "Weapon Proficiency" only — a binary can-use/can't-use flag per weapon category, no per-weapon special property usable only by the proficient (`dnd_basicrules_2018/docling.md:2638`, `:313`). Armor is handled purely under "Armor Proficiency" (implicit; e.g. dwarves get "armor proficiency" at line 679 worded as "Dwarven Armor Training" but this is flavor text for an ability, not a formal rules category). | 2024 keeps "Weapon Proficiencies" (`srd_cc_v5.2.1/docling.md:258`, per-class rows e.g. 1520) as the base gate on attack-roll proficiency bonus, but layers a wholly new **Weapon Mastery** system on top (Barbarian/Fighter/Paladin/Ranger etc. each get it at level 1, e.g. `:1592-1596`, `:2996-3000`, `:3386-3390`) that unlocks per-weapon "mastery properties" — Cleave, Graze, Nick, Push, Sap, Slow, Topple, Vex (defined `:6102-6134+`) — usable only by classes with the Weapon Mastery feature, and swappable on a Long Rest. Separately, "Armor Training" (`:949-951`, per-class rows e.g. 1521) is now the formal named category for what 2014 called armor proficiency. | Weapon Mastery is a wholesale new subsystem with no 2014 equivalent (see §2/§3). If the codebase's data model only stores "proficient: bool" per weapon (2014-shaped), it cannot represent Weapon Mastery without a new field for "which 2 (or N) mastery properties are currently selected," a "swap on long rest" hook, and a damage/effect table for 8 mastery properties. This is a large addition, not a rename. |
| **Action names and set** | 2014 combat actions: Attack, Cast a Spell, Dash, Disengage, Dodge, Help, Hide, Ready, Search, Use an Object (`dnd_basicrules_2018/docling.md:4323-4406`). | 2024 replaces/renames and adds: Attack, **Magic** (replaces Cast a Spell, also covers magic items/features, `:12539`), Dash, Disengage, Dodge, Help, Hide, **Influence** (new, `:12451`), Ready, **Search** (now has a formal skill-mapping table, `:12696-12707`, vs. 2014's prose-only description at `:4399-4401`), **Study** (new, `:12818`), **Utilize** (renames Use an Object, `:12933-12935`, identical mechanic). | Action-economy code enumerating a fixed action list (e.g. an enum of allowed actions) needs Influence, Study, and Magic added and Cast a Spell/Use an Object renamed if targeting 2024. Search gaining a skill table is a minor UX/DC-mapping improvement, not a mechanical break. |
| **Grappling** | A **contested check**: attacker's Str (Athletics) vs. target's Str (Athletics) or Dex (Acrobatics), target's choice; consumes one of the attacker's multiple attacks if applicable (`dnd_basicrules_2018/docling.md:4490-4498`). Escaping likewise a contested check (4496). | Grapple is now a special use of the **Unarmed Strike attack action**: the attacker makes an attack (an Unarmed Strike), and on choosing the Grapple option the **target makes a Strength or Dexterity saving throw** (target's choice) against a **flat DC = 8 + attacker's Str mod + attacker's Proficiency Bonus** (`srd_cc_v5.2.1/docling.md:12903-12911`). Escaping is now a Str (Athletics)/Dex (Acrobatics) check **against the same flat escape DC**, not a contest against a rolled attacker check (`:12357`). | Structural rules-engine change: 2014's grapple resolves as "opposed roll, higher wins"; 2024's resolves as "static DC set at the moment of the grapple attempt, target rolls a save." A combat resolver written for 2014's contest (roll attacker, roll defender, compare) cannot express 2024's grapple without a different code path (roll attacker once to get a hit/nothing on the Unarmed Strike, compute a static DC, then have the target roll a save against that stored DC — the DC is fixed at the time of the grapple and reused for later escape attempts). |
| **Shoving** | Contested check identical in structure to grappling: Str (Athletics) vs. target's Str (Athletics)/Dex (Acrobatics) (`dnd_basicrules_2018/docling.md:4500-4504`). Effect: prone or pushed 5 ft. | Also folded into Unarmed Strike: target makes a Str or Dex saving throw (target's choice) vs. **DC = 8 + attacker's Str mod + Proficiency Bonus** (`srd_cc_v5.2.1/docling.md:12913`). Effect: pushed 5 ft or prone, attacker's choice — same effect options, different resolution mechanic. | Same structural change as Grappling — contest replaced by save-vs-static-DC. |
| **Two-Weapon Fighting** | A universal combat option available to any character wielding two light melee weapons (no feat, class, or fighting-style prerequisite): Attack action + bonus action off-hand attack with a second light weapon, no ability modifier on the bonus-action damage unless negative (`dnd_basicrules_2018/docling.md:4484-4488`). | The base "attack with the bonus action" mechanic moved into the **Light weapon property** itself (`srd_cc_v5.2.1/docling.md:6074-6076`) — available to anyone wielding a Light weapon, same no-ability-mod-unless-negative rule. But "Two-Weapon Fighting" is now the *name of a feat* (Fighting Style Feat, prerequisite: Fighting Style feature) whose sole benefit is letting you add your ability modifier to that bonus-action attack's damage (`:5940-5944`) — i.e., it removes the "no ability mod" restriction, it doesn't grant the ability to dual-wield at all (everyone already has that via the Light property). | Naming collision risk: code or data keyed on the string "Two-Weapon Fighting" as *the mechanic that lets you dual-wield* will misfire against 2024 text, where that same name refers only to a narrow feat that upgrades an already-universal ability. If modeling 2024, the base dual-wield rule must be attached to the Light weapon property, not to a class feature/feat gate. |
| **Death saving throws / dying / stabilizing / instant death** | 3 successes = stable, 3 failures = death; nat 1 = 2 failures, nat 20 = regain 1 HP; damage at 0 HP = 1 failure (2 on a crit); instant death if remaining damage ≥ HP max (`dnd_basicrules_2018/docling.md:4612-4642`). Stabilize: action + DC 10 Wis (Medicine) check, or Healer's Kit for free (2891). | Identical numbers and thresholds (`srd_cc_v5.2.1/docling.md:845-877`): 3 successes/failures, nat 1 = 2 fails, nat 20 = regain 1 HP, damage at 0 HP = fail (2 on crit), instant death if remainder ≥ HP max. Only procedural wording changed: stabilizing is now explicitly framed as using the **Help action** (`:875`) rather than "use your action" (2014's `:4636` phrasing), and the Healer's Kit stabilize is now framed as a **Utilize action** (`:6635`) instead of a bare "action" (2014 `:2891`). | No mechanical change — safe to treat as edition-agnostic. Only the action-name plumbing (Help/Utilize vs. generic "action") differs, which matters only if the engine's action-economy layer requires a specific named action to authorize the check. |
| **Concentration** | Breaks on: casting another concentration spell, taking damage (Con save, DC = 10 or half damage taken, higher of the two — no stated rounding or cap), incapacitated/killed (`dnd_basicrules_2018/docling.md:4816-4828`). | Same triggers, but DC computation now explicitly states "half the damage taken (**round down**)" and adds an explicit **maximum DC of 30** (`srd_cc_v5.2.1/docling.md:12085-12089`) — neither the rounding direction nor the cap is stated in the 2014 text read here. | Functionally near-identical at normal damage levels; diverges only at very high single-hit damage (>40 damage would imply DC 20+ under both, but at 100+ damage 2014's text is silent on a cap while 2024 explicitly caps at DC 30). A 2014-literal implementation risks an unbounded (and arguably absurd) DC at extreme damage; 2024's explicit cap is the safer rule to encode regardless of which edition is chosen for everything else. |
| **Ritual casting** | Any class feature that grants ritual casting lets you cast a prepared/known ritual-tagged spell without expending a slot, taking 10 minutes longer (`dnd_basicrules_2018/docling.md:4748-4750`). Wizards get a special exception: they can ritual-cast any ritual-tagged spell in their spellbook **without having it prepared** (`:1733`). | Base rule identical: "If you have a spell prepared that has the Ritual tag, you can cast it as a Ritual... 10 minutes longer... doesn't expend a spell slot" (`srd_cc_v5.2.1/docling.md:12680-12682`). Wizards retain the analogous carve-out via the **Ritual Adept** feature: cast any ritual-tagged spellbook spell without preparing it, but must read from the book (`:5121-5123`). | No functional change — Ritual Adept in 2024 is textually equivalent to the 2014 wizard ritual-casting exception, just formalized as a named level-1 feature instead of embedded prose. Safe to treat as edition-agnostic. |
| **Hiding / Stealth and the Invisible condition** | "Hidden" was not a formal named condition. Hiding used a **contested roll**: Dex (Stealth) check vs. the searching creature's Wis (Perception) check or passive Perception, no flat DC, no obscurement/cover precondition stated as a hard requirement (`dnd_basicrules_2018/docling.md:3622-3638`, Hide action at `:4385-4387` cross-referencing "Unseen Attackers and Targets" at `:4442-4450` for the actual mechanical benefit: disadvantage on attacks against you, advantage on your attacks). "Invisible" was a separate condition granting the same attack advantage/disadvantage plus "heavily obscured for hiding purposes" (`:12767-12770`). | **Hidden is merged into the Invisible condition.** The Hide action now requires a precondition (Heavily Obscured, or behind Three-Quarters/Total Cover, and out of all enemies' line of sight) plus a **flat DC 15** Dexterity (Stealth) check; success grants the **Invisible condition** "while hidden," with your check total becoming the DC others must beat with Perception to find you (`srd_cc_v5.2.1/docling.md:12385-12391`). The Invisible condition itself (`:12477-12485`) now bundles: advantage on Initiative, "Concealed" (immune to see-you effects), and attack advantage/disadvantage — i.e., it is the single condition used for both true invisibility and successfully-hidden creatures. There is no separate "Hidden" entry in the 2024 condition glossary list (`:12095-12100`, thirteen conditions listed, none named Hidden). | This is a structural merge, not a naming nit: 2014 code that checks a `hidden: bool` flag independently of an `invisible: bool` flag (as CLAUDE.md's example `CharacterRuntimeState` TypedDict does, with a bare `hidden` key) has no direct 2024 equivalent — 2024 wants hidden creatures to literally carry the Invisible condition (with its full effect list: attack advantage/disadvantage, concealment from see-me effects, advantage on Initiative) rather than a separate weaker "hidden" state. Also the DC mechanic changed from opposed-roll-vs-passive-Perception to a flat DC 15 with a hard obscurement/cover precondition — a hiding check with no cover available is simply illegal RAW in 2024 but legal (if presumably auto-failing per DM judgment) in 2014. |
| **Surprise** | A surprised creature **skips its entire first turn** (no movement, no action, no reaction until that turn ends); determined per-creature by contested Stealth vs. passive Perception at encounter start (`dnd_basicrules_2018/docling.md:4154-4170`). | A surprised creature instead simply has **Disadvantage on its Initiative roll** — it still acts on its normal turn in initiative order, just is more likely to act late (`srd_cc_v5.2.1/docling.md:582`, `:12445`, `:12848-12850`). | Major mechanical change with combat-engine implications: 2014 surprise can fully deny a full turn's economy to the surprised side (huge alpha-strike potential); 2024 surprise only shifts turn order probabilistically. A combat engine's initiative/turn-order and "can this creature act" logic needs an entirely different implementation per edition — 2014 needs a "skip first turn" flag per combatant that suppresses actions/reactions until turn end; 2024 needs only an Initiative-roll disadvantage applied before rolling, with no downstream "can't act" state at all. |
| **Jumping, climbing, difficult terrain** | Long Jump = Str score (half if standing start), 1 ft of jump costs 1 ft of movement (`dnd_basicrules_2018/docling.md:3869-3875`). High Jump = 3 + Str mod (half if standing). Climbing/swimming/crawling costs 1 extra ft per ft (2 extra in difficult terrain) unless you have the relevant speed type (`:3865-3867`). Difficult terrain: 1 extra ft per ft of movement (`:3855-3859`, `:4268-4274`). DC for climbing a slippery/handhold-poor surface is **"at the DM's option"** with no stated number (`:3867`). | Same formulas verified line-for-line: High Jump (`srd_cc_v5.2.1/docling.md:12393-12397`), Climbing cost (`:12071-12073`), Swimming cost (`:12852-12854`), Difficult Terrain cost structurally unchanged. The one numeric addition: climbing a slippery/poor-handhold surface now has an explicit **DC 15** Strength (Athletics) check "at the GM's option" (`:12075`), where 2014 left the DC unstated. Swimming rough water similarly gets an explicit **DC 15** (`:12854`) vs. 2014's unstated DC. | Movement-cost math is unchanged and edition-agnostic. Only the "optional obstacle check" DCs went from unstated (implementation must invent a number, commonly houseruled as DC 10 or 15) to an explicit DC 15 in 2024. Low risk either way; worth standardizing on DC 15 since 2024 makes it official and 2014 never contradicts it. |
| **Cover** | Half cover (+2 AC/Dex save), Three-Quarters cover (+5 AC/Dex save), Total cover (can't be targeted); highest applicable degree only, not cumulative (implied but not stated as explicitly as 2024) (`dnd_basicrules_2018/docling.md:4506-4522`). | Identical bonuses and categories; 2024 explicitly states the non-stacking rule: "If a target is behind multiple sources of cover, only the most protective degree of cover applies; the degrees aren't added together" (`srd_cc_v5.2.1/docling.md:691-695`). | No mechanical change; 2024 just states explicitly what 2014 left to be inferred from the examples. Safe to treat as edition-agnostic. |
| **Resistance/Vulnerability stacking** | Explicit rule already present: "Multiple instances of resistance or vulnerability that affect the same damage type count as only one instance" (`dnd_basicrules_2018/docling.md:4586-4594`). | Same rule, same example structure, restated near-verbatim (`srd_cc_v5.2.1/docling.md:813-819`). | **No change.** Both editions already had this exact non-stacking rule; flagged here only because it was explicitly requested for verification. |
| **Inspiration vs. Heroic Inspiration** | "Inspiration": DM-granted, binary (have it or don't, no stockpiling), spent to gain **advantage on one attack roll, saving throw, or ability check** (`dnd_basicrules_2018/docling.md:1982-1994`). | Renamed **Heroic Inspiration**: still binary/non-stockpiling ("Only One at a Time," `srd_cc_v5.2.1/docling.md:288`), but the spend-effect changed to **reroll any one die immediately after rolling it, must use the new roll** (`:284-286`, `:12379-12381`) rather than granting advantage. Also gains new grant sources baked into rules text (e.g., Human characters start each day with it, `:292`; some class features grant it, e.g. `:3076`, `:5790`). | Real mechanical change, not just a rename: "advantage on a roll" (2014) and "reroll a die you already see" (2024) are different in expected value and in when a player would choose to use it (2024's version can be used reactively after seeing a bad roll on a **d20 with advantage/disadvantage already applied**, rerolling only one of the two dice per the example at `:310` — a 2014 "grant advantage" token cannot express that use case). Any UI/game-loop text or automation that says "advantage" for this token needs updating to "reroll" if targeting 2024. |
| **Multiclassing prerequisites** | References a **Multiclassing Prerequisites table** "in the Player's Handbook" that is not reproduced in the Basic Rules excerpt (`dnd_basicrules_2018/docling.md:3369-3379`) — known from the full 2014 PHB to require specific score minimums per class (commonly 13, but Fighter/Ranger among others require two abilities at 13, e.g. Str/Dex or Str/Wis) rather than a single uniform rule. **Not verifiable from this source** — flagged, not guessed. | Single uniform rule stated explicitly: "you must have a score of at least 13 in the primary ability of the new class and your current classes" (`srd_cc_v5.2.1/docling.md:1306-1310`) — one flat ability-score-13 gate per class's single "primary ability," no dual-ability requirement. | If the 2014 rule is confirmed (via the full PHB, outside these sources) to require dual-ability minimums for some classes, this is a real simplification in 2024, not just a restatement. Do not port a "single primary ability, 13" gate as if it were 2014's rule without checking the actual 2014 PHB table — the Basic Rules excerpt here doesn't contain it. |
| **Multiclassing — Extra Attack / Armor Class interaction rules** | Not present in the Basic Rules excerpt at all (only base multiclassing text at `dnd_basicrules_2018/docling.md:3369-3410`; no "Extra Attack doesn't stack," no "choose only one AC-calculation feature" rule found in this source). | Explicit new rules: Extra Attack from multiple classes doesn't stack (max 2 attacks unless a feature explicitly grants more) (`srd_cc_v5.2.1/docling.md:~1330`), and if multiple features offer alternate AC calculations (e.g., Monk Unarmored Defense + Sorcerer Draconic Resilience) only one can be used at a time (same region). | Not confirmable as a "change" from this 2014 source (may exist in the full 2014 PHB and simply not be excerpted into Basic Rules) — flagged as **absent from the 2014 Basic Rules text, status in full 2014 PHB unknown from these sources**, not asserted as new-in-2024. |
| **Backgrounds granting Ability Score Increases and Origin Feats** | Not present as a mechanic: 2014 backgrounds grant skill/tool/language proficiencies and equipment only; no search hit for "background...ability score increase" in the 2014 source at all. | New mechanic: every background now grants **+2/+1 (or +1/+1/+1) to three listed ability scores** and a specific **Origin feat** (`srd_cc_v5.2.1/docling.md:5584-5588`, plus per-background rows e.g. `:5794`). Ability Score Increases moved from "every class gets a flat ASI feature at certain levels regardless of background" (2014-style, still true in 2024 separately) to *also* being granted at character creation via background choice — this is on top of, not instead of, class-level ASIs. | Confirmed **wholly new in 2024** (see §3). If this codebase's character creation flow builds ability scores solely from point-buy/array/class progression (2014-style) with no background-driven ASI step, any 2024-faithful character creator needs a new step. Not a "difference to reconcile," since 2014 truly has nothing here — a straightforward addition if 2024 is adopted, and a straightforward omission if not. |
| **Monster stat block format** | Single-line `Armor Class N (source)` where source is descriptive prose in parentheses if non-default (e.g., "(natural armor)") — not a structured list of typed AC sources (`dnd_basicrules_2018/docling.md:7201-7203` describes the rule; example blocks throughout, e.g. `:7530` `Air Elemental`, show a flat `Armor Class 15` line). Saving throw bonuses only appear as an explicit "Saving Throws" line for the subset of abilities the monster is proficient in; no per-ability MOD/SAVE split shown for abilities without proficiency. No per-monster "Initiative" line/score. XP appears only inline after "Challenge N (X XP)". | New "AC N / Initiative +N (score)" two-column header row (`srd_cc_v5.2.1/docling.md:17083`, e.g. Aboleth: `AC 17 \| Initiative +7 (17)`), meaning monsters now have an explicit, rollable/static **Initiative score** in the stat block itself. Ability score block shows **MOD and SAVE side by side for every ability**, not just proficient ones (`:17087-17088`, `:17138-17139`) — i.e., every ability row bakes in the save bonus whether or not it differs from the bare modifier. CR line bundles CR, XP, lair-XP variant, and Proficiency Bonus together in one line: `CR 10 (XP 5,900, or 7,200 in lair; PB +4)` (`:17090`). | This is a real schema change relevant to the vendored `data/rules/srd/monsters.json` mentioned in CLAUDE.md: a 2024-shaped monster record needs a new `initiative` field (bonus + optional static score) that 2014 stat blocks never had, and its `armor_class` needs to remain (or become) a bare integer rather than the "list of typed entries" shape CLAUDE.md describes for the current vendored 2014 data — that list-of-typed-entries shape doesn't come from the 2014 rulebook's own prose format (which is a single AC number, see left column), so it's a data-modeling choice made when the 2014 JSON was built, not something forced by the 2014 rules text itself. Either edition's prose format is a single AC integer; a "list of typed AC entries" is an implementation detail neither edition's rulebook prescribes. |

## 2. 2014 Basic Rules mechanics with no 2024 SRD counterpart found

For each, noting whether this reflects the SRD being a *subset* of the full
2024 game (i.e., likely still exists in the full 2024 PHB/DMG/MM, just not
reproduced in the free SRD) versus something apparently dropped from 5e
entirely.

- **The "Adventuring Day XP" table** (`dnd_basicrules_2018/docling.md:12417-12430`) — per-character-level XP-per-day budgeting for pacing a full adventuring day across multiple encounters, plus the accompanying "6-8 medium/hard encounters per day" guidance (`:12409-12411`) and the "two short rests per day" rule of thumb (`:12432-12434`). No equivalent table or explicit guidance found anywhere in the 2024 SRD text searched. **Likely SRD-subset omission** — daily-budget guidance is exactly the kind of DM-facing worldbuilding content the 2024 SRD (aimed at licensing OGL-adjacent third-party content) tends to trim, but it may well still exist in the full 2024 DMG. Flag as unconfirmed for the full game either way.
- **The Encounter Multipliers table and party-size adjustment rule** (`dnd_basicrules_2018/docling.md:12375-12393`) — deliberately and explicitly replaced by the flat per-character-budget model in 2024 (§1 above), not merely absent from the SRD subset. This one reads as a genuine 5e-wide design change (also matches public knowledge of the 2024 "One D&D" encounter-building redesign), not an SRD omission.
- **"Multipart Encounters" guidance** (`dnd_basicrules_2018/docling.md:12395-12399`) — treating encounter waves as separate difficulty calculations, with the one-third-of-adventuring-day rule of thumb. Depends on the Adventuring Day XP table above being present; not found in the 2024 SRD text searched. Likely tied to the same SRD-subset trimming as the Adventuring Day table.
- **"Modifying Encounter Difficulty" step-up/step-down guidance** (`dnd_basicrules_2018/docling.md:12436-12438+`, benefit/drawback pushing difficulty by one step) — not found in the 2024 SRD encounter-building section read (`:13509-13598`), which instead has a "Troubleshooting" section (Many Creatures, Adjustments, CR 0 Creatures, Number of Stat Blocks, Powerful Creatures, Unusual Features) covering similar ground with different, less formulaic advice. This reads as a genuine redesign of the guidance rather than a straightforward omission.
- **Unseen Attackers and Targets as separate combat-chapter prose** (`dnd_basicrules_2018/docling.md:4442-4450`) — mechanically absorbed into the Invisible condition definition in 2024 (§1), not lost, but the 2014 framing as generic "attacking a target you can't see" prose independent of any named condition has no direct textual equivalent; 2024 requires the target to formally have the Invisible condition for the same rules to apply. A DM narrating "it's just dark, no formal Invisible condition, but you still can't see the target" is arguably harder to adjudicate cleanly under 2024's condition-gated phrasing.
- **Explicit wizard-only "prepared spells don't need re-selection for rituals" contrast text** — trivial wording difference already covered in §1's Ritual row; not a separate mechanic, no action needed.

No other 2014 mechanics investigated in this pass (exhaustion, encounter building, weapon/armor proficiency, actions, grappling/shoving, two-weapon fighting, death saves, concentration, spell components/rituals, hiding/invisible, surprise, jumping/climbing/terrain, cover, resistance stacking, inspiration, multiclassing, backgrounds, monster stat blocks) were found to have zero 2024 SRD counterpart — every other 2014 mechanic checked has *some* 2024 equivalent, even where the mechanic itself changed substantially (see §1).

## 3. Genuinely new mechanics in 2024 with no 2014 counterpart

- **Weapon Mastery** (`srd_cc_v5.2.1/docling.md:1592-1596`, `:2996-3000`, `:3386-3390`, `:3673-3677`, mastery properties defined `:6102-6134+`) — Cleave, Graze, Nick, Push, Sap, Slow, Topple, Vex; class feature granting access to 2+ mastery properties, swappable on Long Rest. No 2014 concept of a weapon having a "mastery property" gated behind a class feature.
- **Armor Training as a formally named category** (`srd_cc_v5.2.1/docling.md:949-951`) — 2014 has the same underlying concept (armor proficiency) but never names it "Armor Training" as a formal rules term; this is closer to a rename than a new mechanic, listed here for completeness since it's explicitly called out as new terminology in the task brief.
- **Influence action** (`srd_cc_v5.2.1/docling.md:12451-12469`) — formal action codifying social-interaction ability checks (Willing/Unwilling/Hesitant framework, default DC = higher of 15 or monster's Intelligence score, 24-hour cooldown on a failed attempt). 2014 handled this entirely through unstructured "Social Interaction" prose (`dnd_basicrules_2018/docling.md:4001-4014`) with no action-economy formalization, no explicit DC formula, and no cooldown rule.
- **Study action** (`srd_cc_v5.2.1/docling.md:12818-12832`) — formal action for making an Intelligence check against memory/lore/clues, with an "Areas of Knowledge" skill-mapping table (Arcana/History/Investigation/Nature/Religion). 2014 had no dedicated lore-recall action; this was handled ad hoc as skill checks the DM called for.
- **Initiative score (static)** (`srd_cc_v5.2.1/docling.md:12471-12473`) — an explicit alternative to rolling initiative for combatants (10 + Dex mod, ±5 for advantage/disadvantage), intended for GMs running many monsters at once. No 2014 equivalent; 2014 always rolls initiative.
- **Background-granted Ability Score Increases and Origin Feats** (§1 above) — confirmed wholly new; 2014 backgrounds never touch ability scores or grant feats.
- **Heroic Inspiration's auto-grant sources** (e.g., Human characters starting each day with it, certain subclasses granting it on a Long Rest or at the start of combat) — the token itself existed in 2014 as "Inspiration," but automatic non-DM grant sources are new in 2024; 2014's Inspiration was DM-discretion-only.
- **"Concealed" as a named sub-effect of Invisible** (`srd_cc_v5.2.1/docling.md:12483`) — "you aren't affected by any effect that requires its target to be seen" is a broader, more formally scoped benefit than 2014's Invisible condition text, which only addressed attack roll advantage/disadvantage and hiding-obscurement.
- **Round Down as a named universal rule** (`srd_cc_v5.2.1/docling.md:12684-12686`) — 2024 formalizes "always round down unless told otherwise" as its own glossary entry; 2014 states this only inline where relevant (e.g., ability modifier calculation) without a standalone universal rule entry. Not a mechanical change (2014 rounds down everywhere it specifies rounding too), but worth noting as a documentation/consistency improvement that reduces edge-case ambiguity 2014 left implicit.

## 4. Recommendation

**Overall framing**: this project's CLAUDE.md states the vendored monster
data and encounter-difficulty code are 2014-era, and the Cosmere "Radiant's
Handbook" content is built on the 2014 chassis. Given that, the default
recommendation is **stay on 2014 rules everywhere unless a specific 2024 rule
is a strict improvement in game-table experience with no coupling to other
2014-anchored content** — mixing editions piecemeal is the single biggest
risk this audit should guard against, because several 2024 mechanics are
deeply interlocked with other 2024-only mechanics (see the incoherence
warnings below).

| Mechanic | Recommendation | Reason |
|---|---|---|
| Exhaustion | **Keep 2014** (six discrete effect levels) | The vendored data and any existing condition-handling code almost certainly already encodes the 2014 per-level effect table (per CLAUDE.md's `CharacterRuntimeState` example pattern); switching to 2024's flat d20/Speed penalty is a full rewrite of condition-application code for a rules change with no clear gameplay upside for a single-DM-assisted game. |
| Encounter building / difficulty | **Keep 2014** (thresholds + group multiplier) | CLAUDE.md explicitly says the encounter-difficulty code already implements this system; switching to 2024's flat per-character budget is a substantive rewrite of PolicyEngine-adjacent difficulty scaling for a formula that, while simpler, isn't more "correct" — it's a different design tradeoff, not a bugfix. If revisited, do NOT partially adopt (e.g., new thresholds but keep the old multiplier) — that produces a formula matching neither edition. |
| Weapon Mastery / Armor Training | **Skip (2014 has no equivalent; do not backport)** | Adding Weapon Mastery would require new character-sheet fields, a mastery-property effects table, and a "swap on Long Rest" hook that nothing else in this 2014-anchored codebase expects. Since the vendored data is 2014-shaped, introducing this 2024-only subsystem in isolation would make weapons behave inconsistently (some new "mastery" mechanics layered onto an otherwise-2014 combat resolver) — an incoherent mixed-edition state. Leave weapons at plain 2014 proficiency. |
| Action set (Influence/Study/Utilize/Magic) | **Adopt Influence and Study as extensions, rename Use an Object → Utilize is optional** | These are additive, don't conflict with any 2014 mechanic, and Influence in particular is a strong fit for this project's NPC dialogue pipeline (`agents/npc_controller_agent.py`) — it gives a concrete DC formula (15 or monster INT, whichever higher) and a Willing/Unwilling/Hesitant framework that could directly formalize NPC-interaction resolution instead of ad hoc prompting. Utilize/Use an Object are functionally identical either way — pure naming, adopt whichever the rest of the codebase's action enum already uses (2014-style is likely already there). |
| Grappling / Shoving | **Keep 2014's contested-check model** | The 2024 model (attack roll to initiate, save vs. static DC to resist, no opposed roll) is a fundamentally different resolution mechanic (see §1) that would need a distinct code path in the combat resolver — not a data change. Since encounter difficulty, exhaustion, and monster stat blocks are staying 2014-shaped per the above, keeping grapple/shove as an opposed-check contest keeps one coherent combat resolution model throughout, rather than combat having some interactions resolved as "opposed roll" and others as "attack roll → static-DC save" depending on which 2024 pocket got adopted. |
| Two-Weapon Fighting | **Keep 2014's "universal ability, granted by wielding two light weapons"** | 2024 moves the base mechanic into the Light weapon *property* and repurposes "Two-Weapon Fighting" as an unrelated feat name — adopting 2024's naming here without also adopting the 2024 feat system wholesale would just create a confusing mismatch (a feat name that means something different than what any 2014-trained content author would expect). |
| Death saving throws / dying / stabilizing / instant death | **No decision needed** | Mechanically identical between editions (only action-name plumbing differs). Implement once; it satisfies both editions' RAW simultaneously. |
| Concentration | **Adopt 2024's explicit DC cap of 30 and "round down" wording as a numeric clarification, keep everything else 2014** | This isn't really an edition fork — it's 2024 making an unstated 2014 edge case explicit. Capping concentration-save DC at 30 avoids an absurd/unbounded DC at very high single-hit damage and doesn't conflict with any other 2014 rule; safe to adopt in isolation. |
| Ritual casting | **No decision needed** | Identical mechanics; the Wizard-specific carve-out (Ritual Adept) is textually the same rule under a new feature name in 2024. Implement once. |
| Hiding/Stealth and Invisible/Hidden merge | **Keep 2014's separate contested-Stealth-vs-Perception model with an independent `hidden` state, do not merge into Invisible** | This is the mechanic most likely to already be wired into existing combat/stealth code as a standalone `hidden: bool` (per CLAUDE.md's own `CharacterRuntimeState` example, which lists `hidden` as a top-level field alongside `position` and `initiative` — strongly suggesting the current implementation already treats Hidden as independent of Invisible). Adopting 2024's merge would require re-plumbing every hidden-state check to instead apply/check the full Invisible condition (advantage on Initiative, full concealment-from-effects, etc.), which is a much bigger behavioral change than "being sneaky" should imply, and would silently grant hidden creatures 2024-only side effects (Initiative advantage, "Concealed" immunity to see-you effects) that a 2014-anchored ruleset never intended. |
| Surprise | **Keep 2014's "skip first turn"** | This has the largest combat-engine blast radius of any conflict on this list — 2024's "disadvantage on Initiative" requires no "can this creature act yet" gating at all, while 2014 requires a full turn-suppression flag. Given the combat engine is already built (per CLAUDE.md's "Combat System — FIXED" note) around turn-by-turn state, assume it already encodes 2014-style turn-skipping; switching resolution models here is a rewrite of the initiative/turn-order subsystem for a rules change that's more about game feel (2024 avoids an "auto-loss of a full turn" swing) than correctness. If the alpha-strike severity of 2014 surprise is a real playtesting complaint, treat that as a policy/house-rule question (the project already has a PolicyEngine with RAW/HOUSE/EASY profiles) rather than an edition swap. |
| Jumping, climbing, difficult terrain | **No decision needed; adopt 2024's explicit DC 15 for optional obstacle/rough-water checks** | Base movement math is identical. The only 2024 addition is filling in a DC that 2014 left to DM discretion — pure clarification, no conflict. |
| Cover | **No decision needed** | Mechanically identical; 2024 only states explicitly what 2014 left implicit (non-stacking). |
| Resistance/Vulnerability stacking | **No decision needed** | Already identical in both editions. |
| Inspiration vs. Heroic Inspiration | **Keep 2014's "grant advantage" effect, optionally adopt the name "Heroic Inspiration" if desired for flavor** | The effect itself (advantage on one roll) is simpler to reason about and almost certainly what any existing Inspiration-adjacent code already implements; 2024's reroll-a-die effect requires seeing a roll result before deciding to spend the resource, which is a different UI/game-loop interaction pattern (needs a "show the roll, then offer the reroll" step) that doesn't fit a strict "advantage flag set before rolling" implementation. |
| Multiclassing | **Keep 2014's ability-prerequisite framework where documented, but note the full 2014 table wasn't available in this source** — do not silently adopt 2024's single flat "13 in primary ability" rule as if it were equivalent to 2014's rule, since the 2014 rule (per general 5e knowledge, unconfirmed in this specific source) requires two abilities at 13 for several classes. | Mixing this one arbitrarily risks characters multiclassing under criteria that satisfy neither edition's actual designers' balance intent. If the Cosmere Handbook's classes have their own multiclassing prerequisites already defined against the 2014 chassis, follow that, and cross-check against the full 2014 PHB (not just the Basic Rules excerpt) before finalizing. |
| Backgrounds granting ASIs/Origin feats | **Skip (2014 has no equivalent; do not backport in isolation)** | This is tightly coupled to the 2024 feat system (Origin Feats are a distinct new feat category, see §3) and 2024's revised ability-score-generation flow. Grafting "backgrounds grant +2/+1 to abilities and a feat" onto an otherwise-2014 character creator would double-count or conflict with however the current (presumably 2014-style point-buy/array) ability score generation already works, and would require importing the Origin Feats list wholesale to have anything to grant. Treat as out of scope unless a full 2024 character-creation pass is explicitly planned. |
| Monster stat block format (AC shape, Initiative field, MOD/SAVE display) | **Keep 2014's format; do not add an `initiative` field to monster data without a matching 2024-wide surprise/initiative rework** | The vendored `monsters.json` and the CR/XP/Proficiency-Bonus tables (which are edition-agnostic, see §1) are already 2014-shaped. Adding a 2024-style static Initiative score to monster data only makes sense paired with 2024's Surprise rule (which uses Initiative rolls, not turn-skipping) — importing one without the other is incoherent. The "list of typed AC entries" data shape CLAUDE.md describes for the current vendored data is not mandated by either edition's rulebook prose (both use a single AC integer); that's a separate data-modeling decision for whoever built `monsters.json`, worth reconciling on its own merits regardless of which edition's rules text is followed. |

### Incoherent-mixing warnings (do not adopt these combinations)

1. **2024 Surprise (Initiative disadvantage) + 2014-style monster stat blocks with no Initiative field.** 2024's surprise rule is meaningless without every combatant (including monsters) having an Initiative-roll step to apply disadvantage to; the current 2014-shaped monster data doesn't carry an Initiative modifier as a first-class field the way 2024 stat blocks do (`srd_cc_v5.2.1/docling.md:17083`). Adopting 2024 Surprise alone would need a parallel change to how monster initiative is derived.
2. **2024 Grapple/Shove (attack-roll-initiates, static-DC save resolves) + 2014 Two-Weapon Fighting/Extra Attack accounting.** If grapple becomes "an Unarmed Strike using the Attack action," it now interacts with Extra Attack and two-weapon fighting slots exactly like any other weapon attack (consuming one of your attacks) under 2024 rules — the 2014 grapple rule already independently states this (`dnd_basicrules_2018/docling.md:4492`), so this combination is actually fine either way; noted here only to confirm it was checked, not to warn against it.
3. **2024's merged Invisible/Hidden + a `hidden` field kept as an independent boolean.** If only the *name* "Invisible condition" is adopted for flavor but the actual effect list (advantage on Initiative, "Concealed" full-effect immunity) is not implemented, any code checking for "has the Invisible condition" to grant those broader benefits would silently do nothing for a merely-hidden 2014-style creature — a partial/cosmetic adoption of this merge is worse than not adopting it, since it creates the appearance of the 2024 rule being live without the substance.
4. **Backgrounds-grant-ASI (2024) + a 2014 point-buy/standard-array character creator with no Origin Feats table.** As above (§4 table) — don't add the ASI grant without also importing Origin Feats, or the "feat" half of every background becomes an unfillable dangling reference.
