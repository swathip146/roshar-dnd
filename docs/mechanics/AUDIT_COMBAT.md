## Built but unreachable

> **✅ RECONCILED — 2026-09-12:** This is the ORIGINAL `ac4b680` finding list, kept for the diagnosis. **Current status:** (1) `standard_actions` ✅ registered + 27 tests (`5a0a764`); (2) class-feature effects ✅ fire in combat + Rage/Second Wind/Action Surge selectable (`ceb2b04`, `0de1b62`); (3) `has_line_of_sight` ✅ removed as dead code (`ceb2b04`); (4) resistance/vulnerability/immunity ✅ wired (`eb15312`); (5) monster senses ✅ wired (`eb15312`); (6) legendary/lair actions and (7) instant death ⬜ still absent ("future" scope). See the per-row "Fixed in latest update?" column.

The highest-value finding class. All verified by `grep -rn "<name>" --include="*.py" components/ agents/ core/ orchestrator/ | grep -v tests/` returning only the defining file, or by direct test-file absence.

1. **`components/combat/standard_actions.py`** (1076 lines) — Grapple, Shove, Help, Disengage, Hide, Search, Ready, TwoWeaponAttack. `register_standard_actions()` (line 1037) has exactly one match repo-wide: its own definition. **Zero test files** (`find tests -iname "*standard_action*" -o -iname "*grapple*" -o -iname "*shove*"` → empty). This is the single largest chunk of dead combat code in the repo — 8 of the 11 PHB 2024 actions this audit was asked to check for.
2. **Class feature *effects*** (`components/combat/class_features.py`'s `ClassFeatureEngine.use()` and its `_effect_*` methods) — passive granting is wired (character creation, level-up), but nothing calls `.use()` from a combat turn. A Barbarian's Rage, a Fighter's Second Wind/Action Surge, a Rogue's Sneak Attack, a Paladin's Divine Smite: all computable, none triggerable by a player or NPC AI. **Zero test files.**
3. **`TacticalGrid.has_line_of_sight()`** (`tactical_grid.py:257`) — a second, grid-based LOS check with no callers anywhere, including its own tests. The engine's sense-based LOS check is what's actually load-bearing; this one is orphaned.
4. **Damage resistance/vulnerability/immunity wiring** — not a whole module but a wiring gap of the same shape: the engine (`dnd/blocks/health.py`) and the SRD data (`monsters.json`) both have full support, but `dnd_engine_wrapper.py` and `npc_stat_generator.py` never connect them. A zombie's authored poison immunity has zero effect in play.
5. **Monster senses from stat blocks** (darkvision, blindsight, etc.) — `npc_stat_generator.py` never surfaces a senses field; only the distance-based generic sense-refresh mechanism (unrelated to stat-block senses) is reachable.
6. **Legendary actions and lair actions** — not unreachable, simply nonexistent; listed here because they were on the audit brief and the honest answer is "there is no code to be unreachable."
7. **Instant death from massive damage** — same as above: not partially built, just absent, despite a comment implying it exists ("handled separately").

## Biggest surprise

The handoff document says of `class_features.py`: *"NO TESTS, NO REGISTRATION FUNCTION FOUND... this needs the most scrutiny of anything in this handoff... verify which (if any) actually have working code vs docstring-only stubs."* That framing turned out to be too pessimistic in one respect and exactly right in another: the *granting* half is real, tested-by-proxy (visible in live log output, `"🎖️  Hero gains: Second Wind, Action Surge"`), and wired into the single production character-creation path — it doesn't need a `register_*` function because `CharacterManager` calls it directly. But the *using* half — the actual `ClassFeatureEngine.use()` that applies Rage's damage bonus or Second Wind's heal — has a fully-built effect interpreter (heal, grant-action, melee-damage-bonus effect types) that is **completely unreachable from any player or NPC action**, with zero test coverage to even notice. It sits in exactly the same "computed but never triggered" trap as `standard_actions.py`, just one layer deeper: this project's defining failure mode reproduced itself a ninth time, inside a module whose own commit message ("Close the tactical layer...") suggests it was believed finished.
